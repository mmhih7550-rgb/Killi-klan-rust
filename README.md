# CLAN KILLI — платформа клана (BY FREAK)

Полноценная full-stack платформа клана Rust: реальная авторизация Steam OpenID и Discord OAuth2,
заявки в клан в базе данных, чат в реальном времени (SSE), загрузки файлов, раздел KILLI ULTIMATE APP
и закрытая админ-панель владельца.

Стек: Node.js + Express 4 + better-sqlite3 + SSE + vanilla ES-модули (без сборки).

## Быстрый запуск

```bash
npm ci
PORT=3000 npm start        # http://localhost:3000
curl localhost:3000/healthz     # JSON-статус и /api/health (если /healthz перехватывает edge-прокси)
```

Локальные данные (SQLite и загруженные файлы) создаются автоматически в `data/`.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `PORT` | Порт HTTP-сервера (в Docker — `80`). |
| `HOST` | Интерфейс прослушивания, по умолчанию `0.0.0.0`. |
| `DATA_DIR` | Каталог данных (БД + загрузки), в Docker — `/data`. |
| `APP_BASE_URL` | Публичный адрес сайта, например `https://killi.example.com`. Нужен для корректных OAuth-callback и абсолютных ссылок. |
| `STEAM_API_KEY` | Ключ Steam Web API — https://steamcommunity.com/dev/apikey |
| `DISCORD_CLIENT_ID` | ID приложения Discord — https://discord.com/developers/applications |
| `DISCORD_CLIENT_SECRET` | Секрет (OAuth2) того же приложения Discord. |
| `KILLI_OWNER_PASSWORD_1` | Первый пароль владельца при первичной инициализации БД. |
| `KILLI_OWNER_PASSWORD_2` | Второй пароль владельца при первичной инициализации БД. |

> В репозитории нет ни одного реального секрета. Ключи OAuth задаются только переменными окружения
> на сервере (или через панель хостинга) и никогда не попадают в клиентский код.

## Где подключить Steam и Discord

1. **Steam**: получите API-ключ по ссылке выше и задайте `STEAM_API_KEY`. Адрес возврата (OpenID
   `return_to`), который принимает сайт — `${APP_BASE_URL}/auth/steam/callback`. Отдельно
   регистрировать его в Steam не нужно: OpenID 2.0 не требует whitelist, достаточно, чтобы домен
   совпадал с указанным в ключе.
2. **Discord**: создайте приложение, в разделе *OAuth2 → Redirects* добавьте
   `${APP_BASE_URL}/auth/discord/callback`, скопируйте Client ID и Client Secret в
   `DISCORD_CLIENT_ID` и `DISCORD_CLIENT_SECRET`.
3. Задайте `APP_BASE_URL` равным публичному адресу сайта и перезапустите процесс.

Пока ключи не заданы, карточки входа показываются как недоступные (`.is-dim`), а в разделе
аккаунта выводится подсказка, где взять ключи. Это единственное, что нельзя проверить без
владельца проекта: сам OAuth-обмен требует зарегистрированных callback URL и живых ключей.

## Вход владельца (скрытая админ-панель)

1. В футере сайта нажмите **BY FREAK** пять раз — откроется окно входа (это только способ открыть
   форму, а не защита).
2. Введите первый пароль, затем второй. Оба хранятся на сервере **только в виде scrypt-хешей**
   с индивидуальной солью — в HTML/JS и в разметке страницы их нет.
3. При первом входе задайте собственные пароли и включите 2FA (TOTP): панель принудительно требует
   смены стартовых паролей.

### Пароли владельца и их ротация

- Стартовые пароли можно задать только переменными окружения `KILLI_OWNER_PASSWORD_1` /
  `KILLI_OWNER_PASSWORD_2` (или значениями по умолчанию, зашитыми в виде хешей в `server/db.js`).
  В репозитории нет открытых паролей — только хеши.
- Пара паролей версионируется: при смене версии креденшелов (`CREDS_VERSION` в `server/db.js`)
  сервер при следующем старте перезаписывает **оба** хеша в существующей базе (в том числе в `/data`),
  сбрасывает счётчик неудач и удаляет все активные админ-сессии. Именно так старые пароли
  перестают работать на уже развёрнутом сайте.
- Если задана переменная `KILLI_OWNER_PASSWORD_*`, её значение имеет приоритет над базой и при
  следующем старте заменяет сохранённый хеш.
- В разделе **Безопасность** панели владельца первый и второй пароль меняются **независимо**:
  `POST /api/owner/security/password` с `which: "first" | "second"`, текущим значением этого слота
  и (если включена) 2FA-кодом. После сохранения прежнее значение этого слота сразу перестаёт
  работать, второй пароль остаётся неизменным.
- Новый пароль: минимум 10 символов и не совпадает с другим слотом.

Защита входа: scrypt-хеши с солью, серверный rate-limit по IP, временная блокировка при переборе,
TOTP-2FA, серверные сессии и проверка роли владельца на каждом запросе к `/api/owner/*` и
`/api/admin/*`. Прямой переход на `#/admin` без сессии данных не отдаёт — все ответы API требуют
активной owner-сессии.

Обычные посетители не видят ни обратного отсчёта, ни счётчика оставшихся попыток: ответы на
неверный пароль нейтральны (`Неверный пароль.`), а блокировка действует только на вход в
админ-панель. Аккаунты игроков, чат и загрузки от неудачных попыток владельца не блокируются.
Зарегистрировать нового администратора через публичную форму невозможно.

## Роли и доступ

| Роль | Права |
| --- | --- |
| Гость | Публичные страницы, новости, заявка (после входа), публичные загрузки. |
| Пользователь | Профиль, привязка Steam + Discord, подача заявки, её статус. |
| Участник | Чат клана, список участников, скачивание файлов клана, KILLI ULTIMATE APP. |
| Модератор | Модерация чата, жалобы, блокировки. |
| Владелец | Вся админ-панель: заявки, состав, файлы, версии приложения, Discord, новости, дизайн, безопасность. |

Все проверки прав выполняются на сервере при каждом запросе; интерфейс лишь скрывает элементы.

## Админ-панель (10 разделов)

Заявки (с фильтрами по специализации и часам, включая «Исключения») · Участники · Чат ·
Загрузки · Приложение · Discord · Новости · Статистика · Безопасность · Дизайн.

Изменения ссылок Discord (основная и для исключений), названия, логотипа, фона, цветов и описания
сохраняются в БД и сразу применяются на всём сайте.

## Заявки и анкета «Кто ты в Rust?»

Анкета включает 5 специализаций (COMBAT, BUILDER, FARMER, ELECTRIC, OTHER) с выбором основной и
дополнительных ролей, диапазоны часов 700–1000 / 1000–2000 / 2000–3000 / 3000–5000 / 5000+.
Минимум для вступления — 700 часов; при меньшем значении доступна заявка с пометкой «Исключение»
и обязательными пояснениями, которая отдельно выделяется в админ-панели.

Статусы заявки: `pending` → `accepted` / `rejected` / `info_requested`. Решение принимает владелец,
все заявки хранятся в SQLite.

## Загрузки и KILLI ULTIMATE APP

Файлы загружаются через админ-панель (черновик → публикация), хранятся в `DATA_DIR/uploads`,
скачивание доступно только участникам клана. Раздел приложения показывает актуальную версию,
историю обновлений, размер и дату — без обещаний «обнаружения всех читов».

## Чат

SSE (`/api/chat/stream`), сообщения в БД, удаление своих сообщений, модерация, жалобы и блокировки.
События шины: `ready`, `message`, `message_deleted`. Чат доступен только принятым участникам и
модерации.

## Проверки

```bash
npm run check                 # статический аудит: парсинг модулей, маршруты, SSE-события, CSS-классы
node scripts/browser-check.js # реальный Chromium: desktop + mobile, 9 маршрутов, API-статусы
```

`scripts/browser-check.js` требует Playwright и Chromium; путь к бинарнику можно задать через
`CHROME_PATH`.

## Деплой (Docker)

```bash
docker build -t clan-killi .
docker run -p 80:80 -v killi-data:/data \
  -e APP_BASE_URL=https://killi.example.com \
  -e STEAM_API_KEY=... -e DISCORD_CLIENT_ID=... -e DISCORD_CLIENT_SECRET=... \
  clan-killi
```

Образ слушает `0.0.0.0:80`, работает от непривилегированного пользователя, healthcheck —
`GET /healthz`. Каталог `/data` стоит смонтировать как том, иначе база и загрузки потеряются при
пересоздании контейнера.
